----------------------------------------------------------------------------------------
(2) T normalization -- what the code actually does (project/01b_stock_variables.py)
----------------------------------------------------------------------------------------
prices.index (stock_prices_monthly.parquet): 1988-01 .. 2023-12  (N=432)
factors.index (factors_monthly.parquet):     1963-07 .. 2026-04  (N=754)
monthly_idx = intersection(prices, factors, T_raw): 1988-01 .. 2023-12  (N=432)

CODE (verbatim, project/01b_stock_variables.py):
    T_norm = (T_raw_m - T_raw_m.mean()) / T_raw_m.std() * 0.02 + 0.04

This is a FULL-SAMPLE rescale: T_raw_m.mean() and T_raw_m.std() are each a SINGLE
scalar computed ONCE over the ENTIRE monthly_idx span above (1988-01..2023-12, N=432 months),
applied identically to every month. THIS IS NOT AN EXPANDING WINDOW. There is no
24-month minimum, no expanding accumulation, and no month-by-month recomputation
anywhere in this normalization step -- confirmed by reading the code, not inferred.
mean(T_raw_m) = 0.033851   std(T_raw_m) = 0.034429

Consequence: EVERY month's normalized T value (not just the early ones) uses
information from the full sample, including months AFTER that observation --
this is look-ahead for the entire series, not merely an early-sample burn-in
issue as an expanding-window design would produce. This is a DIFFERENT and MORE
SEVERE issue than the one hypothesized in the spec (which assumed an expanding
window with a binding 24-month minimum -- no such construction exists in this
codebase for T; searched project/*.py and robustness/*.py for 'expanding' in the
context of T and found none).

Note for calibration: because T only enters as a STANDARDIZED (near-linear)
rescaling of T_raw applied UNIFORMLY across the sample, and the FM regressions of
interest condition on T contemporaneously within a given month (not on the
normalization constants themselves), the practical channel for bias is mainly
through the T-interaction/Markov-regime classification analyses (Table 4/5) that
use T's LEVEL to split or weight the sample -- exactly the look-ahead concern the
filtered-vs-smoothed Markov probability finding (prior round, DOC1) already
flagged from a different angle. A linear rescale by fixed constants does not, by
itself, change any FM t-statistic that regresses returns on T_z or T*ΔS (since
OLS is invariant to a fixed affine transform of a regressor) -- but it DOES matter
for any split/threshold defined on T's level (regime classification, high/low-T
subsample tests), which use the full-sample mean/std as their reference point.
